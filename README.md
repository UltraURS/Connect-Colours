## 版本与安装

当前版本：0.2.4 测试版（versionCode 17），包名 `io.github.connectcolours`。新增“隐藏类 → 隐藏后台软件”，可多选应用，隐藏最近任务卡片及底部图标。首次需在 LSPosed 新增勾选“系统桌面”（com.android.launcher）并重启；后续勾选或取消勾选，下次打开最近任务生效。真机效果待验证。

从左右边缘向内滑到最大动画位移并连续保持设定时间（默认 0.5 秒，可在模块设置中调整为 0.2–1 秒）后震动一次，返回箭头变为侧边栏图标；松手从相同侧展开系统智能侧边栏。回划会取消整次手势，需松手后重新开始。支持系统桌面；未进入侧边栏待确认状态的有效内滑松手后回原生默认主屏，回划取消不跳页。已适配桌面 13.0.44 的原生 HOME 处理，无需新增桌面作用域。开启本功能时，原有长滑“切换上一应用”让位于侧边栏手势；关闭本功能并重启后恢复原有行为。侧边栏方向通过原生位置接口更新，浮条也会跟随移到触发侧。

模块图标采用用户提供的图1；“模块”和“设置”页共用图2背景，随屏幕比例居中裁剪，叠加浅色遮罩和半透明卡片以保证文字可读。

要求 Android 13（SDK 33）和支持 New XSharedPreferences 的 LSPosed 环境。设置界面使用 LSPosed 的共享偏好桥接，仅共享功能开关；框架未启用或不支持该桥接时会提示并禁用开关，避免保存到目标进程无法读取的位置。实现依据：[LSPosed 共享偏好文档](https://github.com/LSPosed/LSPosed/wiki/New-XSharedPreferences)。

为避免在其他固件上误 Hook，系统界面、设置、无线设置和软件更新的应用版本不符时会跳过该应用，并在模块日志记录 `Unsupported`。STK 已按提供的 13.2.50 APK 核验所需类、字段和方法；结构不兼容时记录 `Unsupported STK implementation`。其他版本以及 `com.android.stk2` 尚未经 APK 核验。

## 已实现的行为

1. 将移动数据磁贴的标题替换为 `今日 123.4 MB` 等流量值。展开快捷设置时刷新，并在显示期间每 30 秒重新读取；原开关、长按与 SIM 卡逻辑保留。
2. 隐藏设置首页的软件更新推荐卡、独立更新入口，以及关于本机顶部的整个 ColorOS 更新卡片；同时过滤设置搜索索引中的相关条目。
3. 拦截“发现系统新版本”和“系统更新已准备就绪”弹窗，并抑制已识别的 OTA 更新通知。
4. 将设置读取的 OTA 红点计数视为零，移除关于本机的更新红点。
5. 在软件更新应用进程内阻止已分析到的 OkHttp、HTTP/HTTPS URL 及 TCP 连接路径，覆盖查询、下载和相关联网请求。不修改系统 hosts，也不是全设备防火墙；不保证覆盖 Recovery、独立系统服务或其他应用的原生联网。
6. 将 OTA 应用读取的 `update_state` 视为无更新状态，使用原生“没有新版本”回调，并让其对外查询接口报告 `have_update=false`。不伪造 Android 版本、安全补丁日期或系统构建号。
7. 在 SIM 欢迎弹窗显示之前拦截，匹配截图中的“尊敬的客户：感谢您选择中国移动通信！”以及“感谢您使用”或“感謝您使用”开头的提示（忽略空白字符）。调用应用原有的“取消”逻辑处理响应、卡槽、超时及关闭。仅处理 STK 对话框 Activity 持有的指定弹窗；未匹配的 SIM 消息和共享进程内其他应用的弹窗保持原逻辑。此规则并非仅限开机时，其他来源或其他文案尚未适配。

全部功能已按用户提供的五个 APK 静态核验。0.2.2 增加无线设置设备选项、后台蓝牙重连和新界面，并保留 0.2.1 的运营商弹窗修复。实际界面、刷新时机和后台行为仍需真机确认。设置搜索客户端可能保留旧索引，切换入口开关后应重启并等待系统刷新索引；若仍出现旧更新条目，请反馈截图和日志，不建议清空整个设置应用的数据。

每个开关只控制对应 Hook，但功能效果会相互影响：例如“显示为无新版本”仍可能让更新红点消失。要完全恢复系统更新行为，请关闭第 2～6 项并重启。

## 隐藏后台软件

在模块的“设置 → 隐藏类 → 隐藏后台软件”中勾选应用。列表显示图标、名称和包名，默认名单为空，支持多选并自动保存。顶部搜索栏按应用名称筛选，英文不区分大小写；已勾选的应用始终优先显示，取消勾选后恢复到未选分组。搜索不会清除已保存的选择。需要读取全部已安装应用，因此声明应用列表可见性权限；列表只在本机用于选择隐藏对象。

- 卡片和底部图标按同一名单过滤，应用进程、通知和桌面入口不因勾选而被关闭。
- 修改后下次打开最近任务生效，不需要保持模块运行或为模块开启自启动。取消选择后恢复仍存在的任务，不重建已被清除的任务。
- 分屏组合仅一侧被选中时保留另一侧的单应用卡片；全部被隐藏时走原生空列表处理，不留下底部图标。
- 适配系统桌面 13.0.44、Android 13，只处理当前用户的任务；工作资料、应用分身等其他用户任务不随同名包一起隐藏。
- 首次覆盖安装后，在 LSPosed 勾选“系统桌面”并重启。其他功能仍使用原有作用域。
- 隐藏功能不提供保活或清理白名单，系统自身后台管理和清理仍生效。显示、恢复、分屏点击、清除和动画需在真机验收。

## 蓝牙自动连接

在“设置 → 蓝牙 → 已配对设备 → 设备详情”底部增加“Connect Colours”分类：

- **自动连接**：每台设备默认关闭。开启后显示“尝试连接次数”，可选 1～5，默认 **1 次**，包含首次尝试。
- 开启设备选项、手机重启或蓝牙重新开启时，未连接的已配对设备开始一轮重连；已连接的设备意外断开时开始新一轮。
- 每次最多等待 **15 秒**；未成功则等待 **10 秒**后发起下一次，超过次数停止。连接接口立即报告失败时直接进入 10 秒间隔。
- 在已适配的无线设置或系统界面中手动断开设备，会暂停该设备的模块重连，直到重新开启蓝牙或重启手机。其他应用主动断开的行为未纳入手动断开识别。
- 每台设备的开关、次数、暂停状态独立保存；取消配对会移除配置。更改次数会重新计算该设备的本轮尝试预算。
- 后台任务仅运行在 SystemUI 主进程，退出设置页面仍有效；定时器采用该宿主已有的 AlarmManager 机制，空闲或耗尽次数后不持续轮询。
- 无线设置和 SystemUI 使用自身已有的 `WRITE_SECURE_SETTINGS` 权限读写 `Settings.Secure` 中的 `connect_colours_bluetooth_` 专用条目；不覆盖系统原有键，不需要给模块授予此权限。系统配置变更通知用于同步设备选项，不启动模块程序。关闭模块并重启后这些条目不会自行执行重连；取消配对时会清理对应设备条目。
- 模块设置中新增默认开启的“蓝牙重连提示”：每次开始尝试用 Toast 显示设备名和次数进度，成功立即提示，全部次数耗尽才提示最终失败。关闭它只关闭提示，不关闭自动重连；修改后重启手机生效。

这里限制的是**模块主动发出的连接请求次数**，不接管蓝牙系统或设备本身的自动连接机制，不修改通话音频、输入设备等原有开关。关闭自动连接会停止后续模块请求，不主动断开已经连接的设备。

## 三键截图

在“设置 → 截屏”中，“电源键+音量减键”下方新增“电源键+音量减键+音量加键”：

- 三键选项默认关闭；开启它自动关闭原双键选项，开启原双键选项自动关闭三键，允许全部关闭。
- 亮屏时三键在 150 毫秒内按下，且三键同时保持按下时触发一次普通全屏截图；松开全部按键后可以再次触发。重复按键事件不重复截图。
- 使用系统原生截图流程，保留系统预览等行为；不绕过安全窗口或系统截图限制。
- 识别窗口内短暂延后相关原生组合键动作，三键成功后取消本次待执行动作，并保留原生松键清理。未凑齐三键时不触发新截图。实体音量、锁屏、电源菜单及无障碍组合的实际冲突处理仍需真机验收。
- 开关通过系统配置保存，不依赖模块自启动。截屏页面内的开关即时生效；模块设置里的“三键截图选项”总开关修改后重启生效。
- 建议验收：分别开启双键、三键验证互斥，测试三键的不同按下顺序、仅按一键/两键、按住不放不重复截图，以及关闭三键后原功能恢复。

## 流量口径

按手机当前时区，自当天零点至今的所有 SIM 卡移动数据接收量加发送量，不包含 Wi-Fi。显示单位按 1024 换算；使用 Android NetworkStatsManager 的历史统计，可能有系统统计延迟，未必与运营商计费完全一致。查询在独立后台线程运行；失败或缓存跨日时保留原标签，不显示虚假的零流量。

统计接口依据：[Android NetworkStatsManager](https://developer.android.com/reference/android/app/usage/NetworkStatsManager)。

## 恢复与排查

在 LSPosed 中停用模块并重启，即可恢复原系统逻辑。模块不删除 OTA 数据、不禁用系统包、不修改系统分区；已经取消的通知由系统后续重新生成。它不会撤销已经进行中的底层安装或已写入的更新。

真机验收建议：

- 展开快捷设置，确认流量标题显示，点击移动数据仍可开关；切换 SIM 卡与飞行模式时状态正确。
- 检查设置首页推荐卡、关于本机红点、关于本机顶部更新卡片及设置搜索。
- 打开设置并正常使用手机，确认不再弹出更新提示；如通过其他路径打开软件更新，确认进入无更新状态。
- 停用模块并重启，确认原界面和更新逻辑恢复。
- 打开桌面程序，确认主页与设置两页、激活/未激活状态、功能分类和各个开关保存正常。
- 新勾选“无线设置”后重启；分别为两台已配对设备设置开关和次数，验证互不影响。退出设置，测试意外断开重连、次数耗尽、手动断开后暂停、蓝牙重启恢复、取消配对清理。
- 插卡重启，确认欢迎提示消失，SIM 菜单仍可正常使用；双卡设备分别验证两张卡。如仍弹出，请提供 LSPosed 模块日志及弹窗截图；更换 SIM 卡应用版本时再提供新 APK。

如某项不生效，请导出 LSPosed 日志中包含 `[Connect Colours]` 的记录，同时提供问题截图。日志包含各应用加载结果、版本不匹配、Hook 安装及流量读取异常。

## 构建与验证

运行 `./tools/test-core.ps1`，检查日期边界、跨年、夏令时、流量格式和超过 32 位整数范围的流量。`./build.ps1` 执行基础检查、Android 单元测试、Lint 和 APK 构建。

首次从 GitHub 构建请先阅读 [BUILDING.md](BUILDING.md)，准备工具、联网下载依赖及测试运行库。

构建配置使用 Android SDK 35 / Build Tools 35.0.0、AGP 8.7.3、Gradle 8.9、JDK 21、Xposed API 82。构建脚本默认读取隔壁 `xbst enhance/.tooling` 的 SDK 和 Gradle，也接受 `-SdkRoot`、`-JdkHome`、`-GradleHome`。

本工程的 Gradle 依赖缓存位于 `.tooling/gradle-cache`，已从隔壁复制；离线 Android 测试运行库位于 `.tooling/robolectric`。新环境需准备同样的依赖缓存和 `android-all-instrumented-13-robolectric-9030017-i7.jar`。这些工具和用户提供的系统 APK 均不打包进模块。

`python tools/verify-apk-hooks.py` 使用 `.tooling/apks` 中的五个 APK（含 `stk.apk` 和 `wireless.apk`）直接核验 DEX 声明，避免使用 jadx 生成的字段别名。适配证据见 `tools/adaptation.md`，构建记录见 Release 附带的 `build-info.json`。

已发布版本的本地验证结果见 Release 附带的 `build-info.json`。0.2.2 增加了重连次数与超时、失败广播不重置预算、手动暂停、设备配置隔离与持久化、无模块 Provider 的配置读写、旧界面配置不覆盖手动暂停、无关系统配置通知过滤、Toast 结果判定、双页导航与设置保存测试，并在原生图形模式下渲染界面进行检查。测试环境不能替代真实设备上的蓝牙连接和 LSPosed 跨进程运行验证。
